# Como contribuir

1. Crie uma branch curta a partir de `main`.
2. Mantenha regras de negócio puras e testáveis.
3. Não adicione dados simulados ao fluxo principal.
4. Preserve os nomes oficiais das categorias junto aos rótulos cidadãos.
5. Rode lint, tipos, testes e build antes de abrir um pull request.
6. Não versione `.env`, arquivos brutos da CEAP, caches ou builds.

Mudanças de linguagem devem manter neutralidade e clareza. Alterações na integração devem citar o contrato oficial validado.
